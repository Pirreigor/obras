CONTEXTO DEL PROYECTO "OBRAS"
=============================
Actualizado: 2026-08-17

QUE ES
------
Sistema de seguimiento de proyectos de construccion para una constructora.
Nace como un sistema TOTALMENTE APARTE del sistema de joyeria (Don Joyero,
carpeta ../joyeria), para que el equipo de la joyeria no tenga ninguna
visibilidad ni acceso al de la constructora, ni viceversa.

DECISIONES TOMADAS (y por que)
-------------------------------
1. Repo propio, sin relacion con joyeria.
   - joyeria/ es un solo repo git con admin/backend/frontend adentro.
   - obras/ es OTRO repo git independiente (git init propio en esta carpeta),
     para que no comparta historial ni acceso con joyeria.

2. Dominio: subdominio gratis en vez de comprar un dominio nuevo.
   - Se eligio obras.donjoyero.com (subdominio del dominio que ya existe
     para la joyeria) en vez de pagar por un dominio nuevo tipo .com/.pe.
   - Falta: crear el registro DNS para obras.donjoyero.com apuntando a la
     futura app de DigitalOcean.

3. Base de datos: nueva DB dentro del MISMO cluster de Postgres de DO.
   - La joyeria usa un cluster de Postgres administrado en DigitalOcean
     (base "defaultdb", host tipo joyeria-db-do-user-xxxx.g.db.ondigitalocean.com).
   - Para obras se decidio crear OTRA base de datos ("obras_db") dentro de
     ese MISMO cluster (ahorra costo, DO lo permite gratis), pero con un
     USUARIO de Postgres propio y distinto (no reusar "doadmin" ni el user
     de joyeria), con permisos solo sobre obras_db. Asi ni con la connection
     string se puede tocar la data de joyeria.
   - Alternativa descartada (mas cara pero con aislamiento total): un
     cluster de Postgres separado.

4. Despliegue: mismo Droplet que joyeria, carpeta y proceso separados.
   - CORREGIDO 2026-08-17: joyeria NO esta en App Platform, esta en un
     Droplet propio: ubuntu-s-1vcpu-1gb-nyc3, IP 104.131.19.189, NYC3,
     Ubuntu 24.04, 1GB RAM / 25GB disco. Sirve con Nginx (+ probablemente
     PM2) desde /var/www/joyeria.
   - obras va en el MISMO Droplet (no se crea un Droplet nuevo), pero en
     su propia carpeta /var/www/obras, con su propio proceso PM2 (puerto
     distinto, ver backend/.env.example -> 4100) y su propio bloque de
     server Nginx para obras.donjoyero.com (con su propio certificado
     TLS via certbot).
   - OJO: el Droplet es de 1GB de RAM. Correr joyeria + obras a la vez
     (2 procesos Node) ahi puede ir justo de memoria; conviene monitorear
     uso (free -h, pm2 monit) al desplegar y considerar upgrade de
     Droplet si se ajusta.
   - Pendiente confirmar: si joyeria realmente usa PM2 y en que puerto,
     revisando la config del Droplet por SSH antes de desplegar obras.

5. Stack tecnologico (igual al de joyeria, por consistencia):
   - Backend: Node.js + Express 5 + Prisma ORM + PostgreSQL. JS plano
     (sin TypeScript). Auth con JWT + bcrypt.
   - Frontend: React 18 + Vite. JS plano.

MODELO DE DATOS (MVP actual)
-----------------------------
Usuario: id, name, email, passwordHash, rol (ADMINISTRADOR | SUPERVISOR)
Proyecto: id, nombre, descripcion, cliente, ubicacion, estado
  (PLANIFICACION | EN_PROGRESO | PAUSADO | FINALIZADO | CANCELADO),
  presupuesto, fechaInicio, fechaFinEstimada, responsable (Usuario)
Avance: id, proyectoId, titulo, descripcion, porcentaje, imagenes[],
  creadoPor (Usuario), createdAt

Esto es un punto de partida razonable, pero NO se termino de conversar con
el usuario que campos exactos necesita para el seguimiento de obra (fotos,
reportes, checklist de tareas, roles adicionales tipo "cliente" que solo ve
su proyecto, notificaciones, etc.). Conviene retomar esa conversacion antes
de seguir construyendo pantallas.

NOTAS DE SEGURIDAD
-------------------
- backend/.env.example es solo una plantilla, sin credenciales reales.
- backend/.env (con credenciales reales) esta en .gitignore, nunca se
  debe commitear.
- El usuario de Postgres de obras_db debe ser distinto y con permisos
  acotados solo a esa base, aunque comparta cluster con joyeria.
- El JWT_SECRET de obras debe ser distinto al de joyeria (sesiones
  independientes; un secreto compartido permitiria falsificar tokens
  entre ambos sistemas).
